# desktop-app 共享笔记本地缓存方案

状态：审查后修订，待实施。本文新增接口和表结构均为拟定设计。

## 1. 目标和首版范围

共享笔记先同步到 desktop 本地，再由本地 Web API 提供离线只读访问。首版缓存共享目录、当前正文、图片和附件；共享编辑与历史版本共享另立任务。

使用独立缓存表、同步状态和下载队列，隔离个人笔记的 dirty/push 流程。通过新增 /api/shared/... 接口提供能力，保持原有 API 定义兼容。

现有共享关系会被物理删除，普通同步只查询当前用户自己的数据，因此时间戳及个人 USN 都不能完整描述共享撤销。当前历史查询按所有者过滤，共享当前正文不等于授权读取历史。

## 2. 总体流程

首版采用“完整有效共享清单快照＋本地差异对账”，正文和文件仅下载变化版本；暂不实现跨轮增量游标。

```text
认证和能力探测
  → 获取固定共享清单快照，分页写入暂存
  → 完整性检查
  → 事务发布权限、元数据、失效记录和下载任务
  → 后台下载正文与文件
  → 本地只读访问
```

共享同步独立调度，由登录、定时刷新、网络恢复或手工同步触发。不依赖个人 pull/push 成功或个人 USN 变化；同一账号同时只执行一轮清单同步。

## 3. 服务端快照和有效权限

### 3.1 拟新增接口

- GET /api/shared/capabilities：返回协议版本和只读快照能力。
- POST /api/shared/snapshots：创建当前认证账号的清单快照，返回 snapshotId、expiresAt。
- GET /api/shared/snapshots/:snapshotId/items?pageToken=...：返回目录、笔记和文件清单、nextPageToken、complete、总条目数。

快照及分页 token 绑定认证账号。分页读取已物化的固定清单，不能使用对实时变化集合的 offset 分页。续传 token 仅用于本轮快照，不作为下一轮增量游标。

快照生成自身也必须一致：MongoDB 和 PostgreSQL 均需实现一致读取，或使用覆盖共享、分组成员、笔记归属和内容元数据变更的版本校验与重试机制。无法证明生成视图稳定时，不得发布可用于删除对账的完整快照。这是实施前置条件，不能只固定分页结果便宣称已解决。

快照过期、缺页、重复 token、条目数不符或请求失败时，丢弃本轮暂存并重建快照，保留上一轮已发布缓存。只有成功响应明确 complete=true 且总数为零，才能认定有效空清单。

### 3.2 权限合并

服务端计算最终有效可读集合，并复用现有有效编辑权限规则；不得简单对多个来源取最大 Perm。

计算覆盖单篇/笔记本、个人/分组授权、成员加入退出、权限变化、笔记移动、回收站和删除。首版共享集合排除已删除及回收站笔记。

撤销一个授权来源后仍有其他来源的笔记应保留。笔记本失效不能级联隐藏仍被单篇共享的笔记。客户端消费最终有效状态，不把某条关系删除直接当成整篇撤权。

仅单篇共享时，在本地按作者组织“共享文章”虚拟目录。不能为了补齐树结构读取未授权父笔记本的名称或内容。

### 3.3 删除对账

只有完整快照校验成功后，才将上一轮存在而本轮缺失的记录标为失效。分页缺失、网络失败或认证失败都不能触发清空。

快照不是后续下载的授权凭据；正文和文件接口仍需按请求时的实际权限校验。

本地记录明确撤权结果的单调权限代次，并在每轮快照创建请求前保存当前代次。若快照创建期间或之后收到明确撤权，发布该旧快照不得恢复对应资源。只有撤权后重新创建、完整校验成功的快照才可重新授予访问；使用本地代次判断先后，不依赖客户端与服务端时钟一致。

## 4. 账号隔离和本地数据库

### 4.1 账号命名空间

新增本地 account_id，使用 MongoDB 兼容的 24 位十六进制 ID，绑定规范化服务端地址（包括部署子路径）和远端登录用户 ID。

不同服务器即使复制自同一 Leanote 数据库、用户和资源 ID 相同，也使用不同 account_id。主机切换默认创建新绑定，地址迁移需要显式验证，不能自动复用缓存。

所有表、文件路径、下载任务和查询都带 account_id。任务启动时固定账号及认证上下文；账号切换后取消旧任务，并在提交结果前验证上下文仍有效。

### 4.2 新增表

| 表 | 主要字段和约束 |
| --- | --- |
| shared_accounts | account_id、服务端地址、远端用户 ID、协议能力；地址与远端用户 ID 唯一绑定 |
| shared_notebooks | 本地 id、account_id、远端笔记本 ID、作者 ID、已授权父节点 ID、标题、排序、有效权限、发布代次、失效状态；唯一键 (account_id, server_notebook_id) |
| shared_notes | 本地 id、account_id、远端笔记 ID、作者/笔记本 ID、标题/标签/格式、元数据版本、目标正文版本、已缓存正文及其版本/摘要、缓存状态、发布代次、失效状态；唯一键 (account_id, server_note_id) |
| shared_files | account_id、远端笔记/文件 ID、图片或附件类型、标题、大小、目标版本/摘要、本地路径、下载状态；唯一键 (account_id, server_note_id, server_file_id, kind) |
| shared_sync_state | account_id、暂存 snapshotId 和分页 token、最后发布代次、最后权限检查时间、下载完成时间、错误状态 |
| shared_snapshot_items | account_id、snapshotId、条目类型/ID、载荷；用于分页暂存、去重和完整性校验 |
| shared_download_jobs | account_id、资源类型/ID、目标版本、状态、重试次数、下次重试时间、错误；同一资源和目标版本任务幂等 |

远端 ID 不设跨账号全局唯一约束。本地资源 id 同样使用 24 位十六进制 ID。共享笔记可没有可见的真实父笔记本，不建立指向个人 notebooks 表的外键。首版不创建共享历史表。

## 5. 正文与文件协议

拟新增：

- GET /api/shared/notes/:noteId/content：当前正文、明确的正文版本及摘要。
- GET /api/shared/notes/:noteId/files/:fileId：该笔记关联的图片或附件。

每次请求根据认证用户重验有效读取权限。作者由服务端从笔记记录解析，不信任客户端提供的作者身份。文件同时验证与笔记的关联及访问权限。

正文版本必须对应实际响应内容。不能用先读到的笔记 USN 给后来读到的不同正文标记版本；若现有元数据与正文分步写入无法保证一致性，先补齐一致读取或专用正文版本机制。首版不获取任何历史版本，原有历史权限保持不变。

## 6. 发布事务、失败重试和文件存储

### 6.1 事务边界

完整快照发布时，在同一 SQLite 事务内更新元数据、有效权限、失效标记、下载任务和已发布代次。

正文失败后任务必须持久保留；即使下一轮清单没有变化也继续重试。正文、已缓存版本和摘要原子更新。新版本下载失败时保留旧正文并标记 stale，不能将旧正文标成新版本；无正文时标记 pending。

下载完成前再次检查账号、访问状态及目标版本，防止迟到响应覆盖新版或恢复已撤销资源。使用有上限的退避重试，持久记录错误并支持手工重试。

### 6.2 文件缓存

目录使用 cache/shared/<account_id>/...，路径由受控 ID 生成，不将远端文件名直接作为路径。先下载临时文件，验证大小/摘要后原子改名并更新索引；中断后清理无引用临时文件。

正文资源地址映射到有权限检查的本地文件入口，不将缓存目录作为公共静态目录。每次访问都检查对应账号和笔记有效性。撤权先禁止读取，再异步清理；仍被其他有效笔记引用的资源保留相应引用。

正文默认自动下载，引用图片随任务下载。附件默认按需加入队列，提供“下载供离线使用”。设置大小上限、并发限制和文件回收策略；被回收的文件显示“未下载”，不是“已撤权”。

## 7. 离线、认证与撤销规则

| 状态 | 处理 |
| --- | --- |
| 尚无缓存正文 | 提示“请先同步”，不隐式代理远端文档 |
| 缓存可用但刷新滞后 | 允许离线只读，显示缓存时间和待更新状态 |
| 网络错误、快照失败 | 保留上一轮缓存和下载任务，不执行删除对账 |
| 资源接口明确表示已无读取权限 | 禁止该资源读取，取消下载并触发清单重建 |
| 单个文件不存在 | 标记文件不可用，不推断整篇撤权 |
| 认证失败 | 停止网络同步并提示重新登录，不解释为空清单或批量删除 |

首版 stale 表示更新滞后，不是权限租约到期。已有缓存不因刷新超时被禁止离线打开。断网期间无法即时获知撤销，已导出的副本也无法远程收回；保证的是获知有效撤权后立即阻止应用内读取并安排清理。

本地读取要求当前账号会话有效。主动退出后锁定该账号缓存；切换账号不能访问上一账号数据；删除本地账号时清理其共享缓存与任务。网络 token 过期与本地离线登录状态分别处理。

## 8. 本地 Web API 与 UI

- bootstrap、共享列表从当前账号缓存读取，提供本地分页、排序和搜索。
- 文档通过明确资源类型及本地 ID 路由；沿用 noteId 路径时也必须在当前账号内解析。不能全库按 ID 查询后仅设 Writable=false 代替读取授权。
- 保留 Vue 所需 UserId（真实作者）、NoteId 等字段，新增 IsShared、OwnerUserId、Perm、CachedAt、CacheState。Perm 表示服务端有效权限，首版本地 Writable 恒为 false。
- 正文、图片及附件入口都校验账号、笔记有效性和缓存状态。获知撤权后通知 UI 关闭当前笔记并清空正文。
- 本地 Handler 强制拒绝共享保存、移动、删除、恢复、图片/附件上传等写操作；隐藏按钮只负责展示。
- 首版禁用共享历史入口，个人历史功能保持不变。
- 共享缓存不混入个人回收站、搜索或统计；需要合并展示时使用明确范围筛选。

## 9. 兼容与迁移

能力探测支持后才启用共享缓存。明确 unsupported、接口不存在或协议不兼容时显示“服务端不支持共享离线缓存”，暂停定时探测，手工刷新或重新登录可再次检测。非预期响应视为协议错误，不能当成空清单。

认证失败、网络失败分别处理，个人同步仍使用原 API。旧服务器或切换后的服务器不能读取其他账号绑定的缓存。

SQLite 使用独立 schema 版本、事务化增量迁移和新增表。迁移前备份；失败回滚本轮迁移，保留个人数据和同步游标。需测试旧 desktop 对新增表的容忍性，不承诺未经验证的任意降级。

## 10. 后续能力

可靠增量同步需另建覆盖授权、成员、移动/删除、正文及文件变化的日志，定义 tombstone、日志保留、游标过期及完整快照重建。不能用 UpdatedTime 或作者 USN 替代撤权日志。

共享编辑使用独立 shared_outbox，提交时重验有效编辑权限并以明确版本执行 CAS；按真实作者写入，冲突或权限下降时保留本地草稿，不静默覆盖。历史共享另行确定授权范围。

## 11. 实施阶段和验收

1. 服务端：能力探测、一致快照、有效权限、当前正文和文件读取；先解决 MongoDB/PostgreSQL 快照生成及正文版本一致性。
2. 本地数据层：账号隔离、版本化迁移、暂存对账、发布事务和持久下载队列。
3. 同步及 UI：独立调度、文件缓存、离线只读、所有入口访问校验及状态提示。
4. 集成验证：使用临时 MongoDB、PostgreSQL 和 desktop SQLite 验证下列场景。

验收清单：

- 首次同步后断网能读当前正文及已下载文件，未下载附件有明确提示。
- 仅撤销一个授权来源时保留仍可读笔记；最后来源撤销后所有本地入口拒绝读取。
- 分组退出、笔记移动、回收站及删除变化能够通过对账发现。
- 分页失败、过期及认证错误不清空缓存；有效空快照正确失效旧记录。
- 快照生成和分页期间并发变化不造成错误撤权或永久漏项。
- 下载接口先确认撤权、旧快照随后发布时，资源仍不可读；撤权后新建快照确认重新授权才能恢复。
- 正文失败后重启仍可重试；迟到响应不覆盖新版，元数据版本不冒充正文版本。
- 相同 ID 的不同服务器、多账号切换和同步期间切换账号均不串数据。
- 直接调用本地写接口不能修改共享缓存，新接口不能读分享前历史。
- 个人 push 失败不阻止共享权限刷新，共享任务不进入个人 push。
- 数据库迁移失败和旧服务端降级不影响个人笔记。

首版按上述只读范围验收；增量日志、共享编辑和历史共享分别实施。
