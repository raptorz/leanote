# Pearlnote 统一 UI 设计

本文档定义 Web、desktop-app 以及后续移动端应共同遵循的笔记界面结构和交互规则。设计以 `desktop-app` 的三栏笔记工作区为基础，吸收 Web 端已经提供的笔记本搜索、共享笔记和文章信息功能。

功能范围为笔记工作区、账号管理和系统管理。不再提供博客、公开发布、评论、博客主题和预览；笔记的用户间共享继续保留。本文中的分享指权限控制下的笔记共享，不是发布到公开博客。

## 设计目标

- 各端保持相同的信息层级、主要操作位置和交互语义。
- 桌面端优先保证高频的“选笔记本—选文章—编辑文章”流程。
- Web 端和 desktop-app 使用相同的 API 数据模型，不因布局调整改变现有 API 路径、参数和字段。
- 在窄屏设备上允许折叠侧栏，但不隐藏核心功能。

## 总体布局

工作区采用“最左全局导航 + 三个工作区面板”的结构：

```text
┌──────────┬──────────────┬──────────────┬────────────────────────┐
│ 全局导航 │ 笔记本/共享栏 │ 文章列表     │ 编辑器                 │
│ 用户菜单 │ 搜索笔记本    │ 搜索/排序     │ 文章工具栏、Info        │
│ 新建/设置│ 我的笔记本    │ 标签过滤      │ 文章内容                │
│          │ 共享给我      │              │                        │
└──────────┴──────────────┴──────────────┴────────────────────────┘
```

实际实现可将笔记本栏、笔记列表和编辑器作为三个可调宽度面板；最左列始终是全局导航栏。窗口宽度不足时，面板按“编辑器 → 笔记列表 → 笔记本栏”的顺序折叠为抽屉。

### 第一列：全局导航栏

用户菜单从顶部导航或右侧区域移动到最左列，作为全局入口。顺序建议如下：

1. 产品标识/返回工作区
2. 新建文章
3. 搜索文章
4. 笔记本
5. 共享
6. 用户头像和用户菜单
7. 设置、帮助、退出

用户菜单至少包含：账号资料、修改密码、邮箱、显示设置、退出登录；管理员额外显示系统管理入口。菜单应固定在第一列底部，头像、用户名和展开图标同时支持点击。不提供博客及博客主题设置。

### 第二列：笔记本与共享栏

第二列保留 desktop-app 的笔记本树作为主导航，并增加 Web 端已有功能：

- **搜索笔记本**：位于笔记本树上方，支持按名称实时过滤；过滤只改变显示结果，不改变数据。
- **我的笔记本**：显示笔记本树、文章数量和当前选中状态。
- **共享给我**：单独分组显示他人共享的笔记本或文章，并使用共享图标标识。
- **标签**：如当前端已有标签入口，放在笔记本和共享分组之后。
- **折叠状态**：保留展开/收起状态；收起后通过第一列的笔记本、共享图标打开抽屉。

新建文章、移动文章和新建共享文章的笔记本选择器也必须提供笔记本搜索，并使用同一套过滤规则。

### 第三列：文章列表与编辑器

第三列由文章列表和编辑器组成：

- 文章列表显示标题、摘要/预览、更新时间和未保存状态。
- 支持列表/摘要两种视图、排序、标签过滤和搜索文章。
- 当前文章使用清晰的选中状态；共享文章显示只读或共享权限标识。
- 编辑器顶部显示文章标题、保存状态和文章工具栏。
- 文章内容区支持富文本和 Markdown，两种模式的工具位置保持一致。

## 文章工具栏

以 desktop-app 现有工具栏为基础，统一保留新建、保存、移动、标签、删除、分享、附件和编辑模式等操作，并增加 Web UI 的 **Info（文章信息）** 按钮。

建议顺序：

```text
保存状态 | 编辑模式 | Info | 标签 | 移动 | 分享 | 附件 | 删除 | 更多
```

Info 按钮打开文章信息面板或弹出层，展示：

- 文章 ID（需要调试时才显示或允许复制）；
- 所属笔记本；
- 创建时间、更新时间；
- 字数/字符数；
- Markdown/富文本模式；
- 共享状态和当前权限；
- 历史版本入口（当前端支持时）。

Info 面板是只读信息展示，不应覆盖编辑内容；在窄屏上使用右侧抽屉或底部弹层。

## 交互规则

- 所有端使用相同的选中、悬停、禁用、保存中和保存成功状态。
- 新建、保存、删除、移动、分享等操作必须提供明确的成功或失败反馈。
- 删除先进入回收站；永久删除必须二次确认。
- 共享文章的只读状态在列表和编辑器中同时体现，禁止仅依靠颜色区分。
- 搜索输入支持清空；无结果时显示空状态和返回全部内容的操作。
- 面板宽度、折叠状态和列表视图可以按端保存为用户偏好，但不影响文章数据。

## 响应式规则

- ≥ 1200px：显示完整三栏布局。
- 768px–1199px：保留第一列和一个主面板，笔记本栏或文章列表以抽屉打开。
- < 768px：使用单面板导航；第一列作为底部或侧边导航，编辑器占满屏幕，Info 和分享使用弹层。
- 键盘快捷键、鼠标和触摸操作都应可用；编辑器获得焦点时不得被全局快捷键抢占。

## API 与实现约束

本 UI 调整不改变现有 API 的路径、参数名和响应字段，以保持 Leanote desktop-app 及旧客户端兼容。新前端需要使用现有接口获取：

- 用户信息和会话；
- 笔记本、共享笔记本及其搜索结果；
- 文章列表、文章内容和文章信息；
- 标签、附件、分享权限和历史版本。

如果现有 API 无法满足某项新交互，应新增接口或可选字段，不修改已有字段含义。前后端分离后，服务端不再通过模板 `ViewArgs` 注入页面初始数据，前端应在进入工作区后按上述顺序加载数据，并显示加载和错误状态。

## 验收标准

- Web 和 desktop-app 的主要工作区均为“最左全局导航 + 笔记本/共享栏 + 文章列表/编辑器”。
- 用户菜单位于最左列，且在窄屏下仍可访问。
- 笔记本栏可以搜索笔记本；新建和移动文章的选择器也支持搜索。
- 共享内容有独立入口和权限状态提示。
- 文章工具栏包含 Info 按钮，打开后能查看文章元数据。
- 现有 API 和旧 desktop-app 登录、同步、编辑流程不受影响。
