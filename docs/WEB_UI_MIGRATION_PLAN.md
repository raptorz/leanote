# Vue Web UI 重写与部署计划

状态：待实施。本文件仅制定计划，尚未实施前端重写或删除旧 UI。

## 目标与边界

依据 [统一 UI 设计](UI.md)，使用 Vue 重写 Pearlnote Web 界面，实现前后端分离。前端构建为 `web/dist`，由现有 Go/Revel 服务端提供静态文件服务。生产环境继续通过原来的域名、端口和路径访问，默认仍为 `http://localhost:9000`，无需额外启动 Node 服务或部署独立前端服务器。

新界面完成并通过功能验收后，移除被替代的旧 Web 模板、页面脚本、样式和渲染代码。保持原有 HTTP API、Leanote desktop-app 兼容性、MongoDB/PostgreSQL 数据访问及迁移能力。本次实施范围是 Web；desktop-app 用作布局和兼容性参照，不在本次重写客户端。

功能范围调整：保留笔记工作区、账号管理和系统管理；不再提供博客、公开发布、评论、博客主题及主题预览。笔记本/文章的用户间共享继续保留。移除功能不意味着删除已有数据库记录；旧 API 字段和同步数据保持兼容。

## 当前基础与需明确的设计

- 页面由 `app/controllers` 配合 `app/views` 渲染，笔记页通过 `ViewArgs` 注入初始数据；部分操作已经使用 JSON 接口。
- `/api/...` 提供客户端接口，但不能假定覆盖共享、管理后台等全部 Web 能力，需要逐项核对。
- `conf/routes` 包含页面、数据、静态资源和通配控制器路由；`app/lea/route/Route.go` 还会改写 `/api` 和 `/member` 的控制器。
- Docker 和 `scripts/build-release.sh` 当前打包 `app/views`、`public` 等目录，需要增加前端构建产物。
- 公开博客、主题和预览的页面及专用渲染逻辑将移除；旧笔记内容可能引用原有资源 URL，不能整体删除 `public`。

实施时先澄清 UI.md 中的布局表述：宽屏为最左全局导航，加笔记本/共享、文章列表、编辑器三个工作面板；文章列表和编辑器各自独立。窄屏优先保留当前编辑器，先收起导航工作面板。用户菜单固定在最左列底部，搜索笔记本、共享和 Info 按要求实现。

## 技术方案

- 前端使用 Vue 3、TypeScript、Vite、Vue Router 和 Pinia，源码集中到 `web/`；实施时选择兼容的依赖版本、固定 Node 版本并提交锁文件。
- Vue Router 使用 History 模式，保持 `/login`、`/note`、`/note/:noteId` 等原路径，不改成 hash 地址。
- API 调用封装在独立服务层，在前端内部转换旧字段和响应格式，不改变服务端旧接口契约。
- 编辑器封装统一适配层，覆盖富文本、Markdown、附件、图片、历史版本和保存状态。正式选型前用真实旧内容验证往返保存、代码块、表格、链接及扩展语法，不能因编辑器更换丢失内容。
- 生产环境前后端同源，浏览器使用相对地址请求；开发时通过 Vite 代理到 Go 服务，默认不引入跨域部署要求。
- 前端版本信息读取项目集中维护的版本来源，避免新增独立维护的产品版本号。

建议目录：

```text
web/
  src/
    api/          # 请求、错误处理与旧接口适配
    components/   # 通用组件和编辑器适配
    layouts/      # 工作区及账号/管理页面布局
    pages/        # 页面
    router/       # 原 URL 对应的客户端路由
    stores/       # 用户、笔记、共享和保存状态
    styles/       # 统一样式与显示设置
  tests/          # 组件及浏览器测试
  dist/           # 构建产物，随发行包交付，不手工维护
```

## 实施阶段

### 1. 建立功能、路由和接口清单

逐项记录旧页面 URL、入口、权限、接口、依赖文件、新页面位置及验收用例。清单至少覆盖：

| 功能范围 | 必须覆盖的行为 |
| --- | --- |
| 首页与账号 | 工作区入口、登录、退出、注册、验证码、找回密码、邮箱验证 |
| 笔记工作区 | 笔记本树及搜索、新建/移动/排序、文章搜索、标签、回收站、批量操作 |
| 编辑器 | 富文本、Markdown、自动保存、历史版本、图片、附件、导入导出、Info |
| 共享 | 共享给我、共享笔记本和文章、成员及权限管理、只读和可编辑状态 |
| 用户中心 | 头像、用户名、邮箱、密码、偏好、现有账号管理功能 |
| 系统管理 | 用户及密码管理、站点配置、注册开关、邮件及其他非博客管理功能 |
| 移除功能 | 博客、公开发布、评论、博客主题及预览，不迁移到 Vue |

将 `/` 和 `/index` 统一作为应用入口：未登录进入登录页，已登录进入 `/note`，不再读取管理员博客首页配置。保留其余在用页面的深链接、查询参数、下载和旧资源 URL。为旧 API 固化路径、参数、响应、认证和同步行为的基线测试。

产出：功能迁移清单、接口缺口清单、资源引用清单和可执行验收用例。

### 2. 搭建 Vue 和 dist 托管骨架

创建前端项目、统一布局、路由、状态和请求层；先完成登录到空工作区的链路。添加 Go 静态服务，支持从配置和应用基准目录解析 `web/dist`，不依赖启动命令的当前目录。

路由规则：

1. API、现有数据操作、上传、下载及文件访问优先匹配，保持原响应语义。
2. 构建资源使用独立路径（例如 `/assets/`），正确返回 MIME；带内容哈希的资源可长期缓存。
3. 已登记的页面 GET/HEAD 请求返回 `dist/index.html`，由 Vue 处理路由；入口 HTML 采用重验证或不缓存策略。
4. 未知 API、缺失资源和非页面请求返回正确错误，不使用全局 HTML 回退；页面不存在时展示 404，并明确 HTTP 状态策略。

同步处理 Revel 自定义路由改写，防止 `/member/...` 页面被分派到旧控制器。缺失 dist 时提供明确启动错误；构建和打包阶段也应检查产物完整性。

验收：同一 Go 端口可以打开和刷新深链接；API、下载、404 及资源缓存行为正确。

### 3. 补齐前端接口与认证链路

复用既有业务 service 和数据库抽象。将页面初始化需要的用户、配置、笔记本、标签等数据改为 JSON 获取；缺少的共享、账号和系统管理能力新增接口，不新增博客接口。

新接口须明确路由映射并避开现有通配路由，不直接假设任意多级 `/api/...` 前缀已受支持。保留旧 API 的路径、参数、字段含义及 token 方式；如新增认证方式，采用兼容扩展。

优先沿用同源会话用于 Web，核对各接口是否完整支持 Cookie 会话、CSRF 防护、退出及密码修改后的会话失效。前端路由守卫只负责体验，资源和管理员权限由服务端校验。图片和附件也要验证浏览器加载时的认证行为。

验收：账号全流程、权限边界和原 desktop-app API 基线通过，MongoDB 与 PostgreSQL 下行为一致。

### 4. 完成笔记工作区

按 UI.md 实现最左列用户菜单、笔记本搜索、共享分组、文章列表和编辑器；补齐标签、排序、移动、复制、回收站及批量操作。Info 展示实际可用元数据，缺失字段明确处理。

实现自动保存、失败重试、离开页面提示及切换文章时的保存顺序，防止延迟响应覆盖另一篇文章。处理 Web 与 desktop 同时修改时的冲突，保持服务端同步序号语义。共享只读、无权限、加载失败和空列表均有对应状态。

验收：普通文章和共享文章从新建到编辑、保存、同步、删除/恢复的完整流程通过；富文本和 Markdown 的旧内容往返保存不丢失。

### 5. 完成账号与系统管理，停用博客

实现账号中心和系统管理页面，保留相应旧入口地址，补齐站点链接及邮件中的跳转验证。移除博客管理菜单、公开发布按钮、博客主题设置、主题上传及预览入口。

停用 `/blog`、`/preview` 及博客专用管理、评论、主题操作路由，返回明确的 404/410，不落入 SPA 回退或通配控制器路由。检查自定义域名和其他博客入口，确保不能继续公开访问。删除博客专用模板与执行逻辑，无需转换或兼容旧博客主题。

保留历史博客数据和客户端契约中的 `IsBlog`、`PublicTime` 等字段，不因 UI 下线重置数据或改变同步语义。逐项核对旧客户端涉及的发布相关 API，保留兼容处理，但不得恢复公开博客页面。笔记共享接口继续按用户身份和权限工作，不能与博客发布一并停用。

验收：账号和系统管理功能及权限通过；博客、主题与预览无法访问；原笔记共享及客户端同步正常。

### 6. 接入构建、Docker 与自动发布

- 本地流程为安装前端依赖、构建 `web/dist`、构建/运行 Go 服务；更新开发启动说明。
- Docker 增加 Node 构建阶段，将 dist 复制到运行镜像；运行时继续使用一个 Go 进程和原端口。
- 发布脚本在打包前构建或接收已验证的前端产物，并确保所有平台发行包包含相同版本的 dist。
- GitHub push 工作流增加前端类型检查、测试和构建；正式 tag 的 release 包与镜像均包含前端产物。
- 检查 `.dockerignore`、忽略规则、Revel `package.folders`、运行路径及 Linux/Windows/macOS 的资源查找。
- 更新 README、部署、快速开始和发布指南，说明前端构建、静态缓存与回滚方式。

验收：从干净检出可以构建；使用发行包或 Docker 不需要 Node 即可通过原地址使用 Web。

### 7. 全面验证、切换与移除旧 UI

先让完整 Vue UI 成为默认入口，再按引用清单清理旧页面模板、jQuery 页面逻辑、样式、旧构建配置和仅用于 HTML 渲染的控制器方法。混合控制器中的 JSON 操作继续保留或兼容转发，业务 service 不随页面删除。

对 `public`、`app/views`、主题目录逐项判断：移除博客专用模板、主题执行逻辑与不再引用的随包资源；用户上传、历史笔记引用资源、邮件模板、PDF/导出模板、必要错误页面不能因目录名称而被批量删除。编辑器自身的皮肤也不是博客主题，应根据新编辑器的依赖决定去留。随后移除相应打包路径和依赖，不清空数据库或用户上传的主题文件。

发布前保存数据库及上传文件备份和上一个完整发行包。UI 切换不改写笔记 ID、密码或数据库内容；如确需数据迁移，使用现有版本化机制并单独说明回滚约束。回滚时恢复匹配的服务端和 dist，不能混用版本。

验收：无旧页面入口和旧页面脚本依赖，所有保留模板都有非旧 UI 的用途说明，完整回归和发行包冒烟通过。

## 测试与完成标准

- 前端：类型检查、关键组件交互、保存竞态和权限状态测试、生产构建。
- 浏览器：原 URL 登录、刷新深链接、账号和管理、笔记编辑/搜索/共享/Info、上传下载及窄屏操作。
- 后端：既有 Go 测试、旧 API 契约、认证/权限、静态文件路径边界、缺失资源和 SPA 回退测试。
- 双数据库：在隔离的 MongoDB、PostgreSQL 测试库执行关键端到端流程；额外验证 PostgreSQL 纯初始化和既有迁移测试。
- desktop-app：登录、全量/增量同步、双向新建修改删除、图片及附件、修改密码后的会话行为。
- 部署：干净构建的 Docker 和发行包使用原端口服务 dist，生产环境无 Node 运行依赖，旧数据和资源链接可用。

上述阶段按顺序推进。最终完成条件是功能清单全部通过、旧 API 兼容、Vue 成为全部被替代页面的入口、旧 Web 实现清理完毕，以及构建和部署文档与实际发行包一致。
